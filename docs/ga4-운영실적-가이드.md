# GA4 운영 실적 모니터링 가이드

도시정비 법률 챗봇(https://jeongbi.explozn87.workers.dev)의 **실사용 건수·질의 유형**을
Google Analytics 4(GA4)로 집계하기 위한 설정·확인 절차.

---

## 1. GA4가 무엇인가 (한 문단 요약)

Google Analytics 4는 구글이 무료로 제공하는 웹사이트 이용 통계 도구다. 페이지에
측정 스크립트를 심어두면 **몇 명이, 며칠에, 몇 번 들어와서, 얼마나 머물렀는지**가
자동으로 집계된다. 여기에 더해 서비스가 원하는 행동을 **맞춤 이벤트**로 직접 심을 수
있어, 이 챗봇에서는 "질문 1건이 오갔다 / 그 질문은 어떤 유형이었다 / 근거를 찾았다"
같은 운영 실적을 그대로 지표화했다. 무료이며, 별도 서버가 필요 없다.

## 2. 이 챗봇이 GA4로 보내는 것 / 보내지 않는 것

### 보내는 것

| 이벤트 | 발생 시점 | 파라미터 |
|---|---|---|
| `page_view` | 로그인 성공(또는 세션 유지 상태로 재접속) 시 자동 | 기본값 |
| `login` | 비밀번호 입력 후 새로 입장할 때 | `method`(=password) |
| `ask_question` | 질문 전송 버튼을 누를 때 | `q_type` 질의 유형 · `scope` 검색범위 · `q_len` 질문 글자수 |
| `answer_shown` | 답변이 화면에 표시될 때 | `q_type` · `scope` · `result` 답변/근거없음/오류/세션만료 · `latency_ms` 응답시간 · `top_law` 인용된 최상위 근거 법령 · `source_count` 근거 개수 |
| `logout` | 로그아웃 클릭 시 | — |

`q_type`(질의 유형)은 질문에 등장한 법률 용어로 분류한다. 분류 표는
`chatbot/public/index.html` 의 `Q_TYPES` 배열 한 곳에만 있으므로, 유형을 늘리거나
키워드를 보완하려면 그 배열에 줄을 추가하면 된다.

> 재건축부담금 · 매도청구·청산 · 수용·손실보상 · 세금 · 관리처분·분양 · 조합·추진위 ·
> 시공자·계약 · 인가·계획 · 소규모주택정비 · 노후계획도시 · 재건축진단 · 신탁방식 ·
> 임대·주택규모 · 기타

### 보내지 않는 것 (의도적으로 제외)

- **질문 원문과 답변 원문** — 사내 사업장·조합명이 섞일 수 있어 전송하지 않는다.
  대신 유형·글자수만 보낸다.
- **사용자 이름** — 로그인 이름은 8자리 해시로 변환해 `user_id`로만 보낸다.
  "몇 명이 실제로 쓰는가 / 재방문하는가"를 세기 위한 최소 정보이며, 해시에서 이름을
  되돌릴 수 없다.
- **비밀번호·쿠키** — 전송 대상이 아니다.

## 3. 설정 절차 (최초 1회)

### 3-1. GA4 속성 만들기 — 측정 ID 발급

1. https://analytics.google.com 접속 → **관리(좌하단 톱니)** → **만들기 › 속성**
   - 계정: 회사 계정(전산팀 관리 계정)으로 만드는 것을 권장. 개인 Gmail로 만들면
     담당자 변경 시 이관이 번거롭다. 부득이 개인 계정으로 만들었다면, 만든 직후
     **관리 › 속성 액세스 관리**에서 전산팀 담당자를 관리자로 추가해 둘 것.
   - 속성 이름: `도시정비 법률 챗봇`, 시간대: `대한민국`, 통화: `대한민국 원`
2. 업종/규모는 아무거나 선택해도 집계에 영향 없음.
3. 플랫폼 선택에서 **웹** → 웹사이트 URL `https://jeongbi.explozn87.workers.dev`,
   스트림 이름 `jeongbi` 입력 → 만들기.
4. 생성된 **측정 ID**(`G-` 로 시작하는 10자리 내외 문자열)를 복사한다.

### 3-2. 챗봇에 측정 ID 넣고 배포

`chatbot/worker/wrangler.toml` 의 `[vars]` 항목에 측정 ID를 붙여넣고 재배포한다.

```toml
[vars]
GA_ID = "G-XXXXXXXXXX"   # ← 3-1에서 복사한 값
```

```bash
cd chatbot/worker
npx wrangler deploy
```

- `GA_ID`를 **비워두면 측정이 완전히 꺼진다**(GA 스크립트를 아예 불러오지 않음).
  잠깐 중단하고 싶으면 값을 지우고 재배포하면 된다.
- 측정 ID는 어차피 페이지 소스에 노출되는 공개 값이라 비밀이 아니다. `wrangler.toml`에
  평문으로 둬도 되고, DeepSeek 키처럼 시크릿으로 관리할 필요가 없다.

### 3-3. 맞춤 정의 등록 ★ 빼먹으면 보고서에 안 나온다

GA4는 **직접 만든 파라미터를 미리 등록해야** 보고서에서 쪼개 볼 수 있다.
등록하지 않으면 "질문 몇 건"까지는 보이지만 "유형별로 몇 건"이 안 보인다.
**등록한 시점 이후에 수집된 데이터부터** 반영되므로, 배포 직후 바로 등록할 것.

**관리 › 데이터 표시 › 맞춤 정의 › 맞춤 측정기준 만들기** — 아래 4개를 등록
(범위는 모두 `이벤트`):

| 측정기준 이름 | 이벤트 매개변수 |
|---|---|
| 질의유형 | `q_type` |
| 검색범위 | `scope` |
| 답변결과 | `result` |
| 근거법령 | `top_law` |

이어서 **맞춤 측정항목 만들기** — 3개 등록:

| 측정항목 이름 | 이벤트 매개변수 | 측정 단위 |
|---|---|---|
| 응답시간 | `latency_ms` | 밀리초 |
| 근거개수 | `source_count` | 표준 |
| 질문글자수 | `q_len` | 표준 |

### 3-4. 데이터 보관 기간 늘리기 (권장)

**관리 › 데이터 표시 › 데이터 보관** → `14개월`로 변경.
기본값(2개월)이면 두 달 지난 실적을 탐색 보고서에서 못 본다.

## 4. 실적 확인 방법

### 즉시 확인 (설정이 잘 됐는지 검증)

**보고서 › 실시간** — 챗봇에 접속해 질문을 1건 던지면 30초 안에 이벤트가 뜬다.
단, 아래 5항의 **제외 계정("박새")으로 접속하면 아무것도 안 잡히는 게 정상**이다.
검증할 때는 다른 이름으로 로그인할 것.

### 정기 보고용 숫자

| 전산팀이 물어볼 것 | 어디서 보나 |
|---|---|
| 실사용 이용 건수 | **보고서 › 참여도 › 이벤트** 에서 `ask_question` 의 이벤트 수 |
| 실제 사용 인원 | **보고서 › 참여도 › 개요** 의 활성 사용자 수 |
| 재사용률(붙박이 사용자) | **보고서 › 유지** 의 재방문 사용자 |
| 질의 유형 분포 | **탐색 › 자유 형식**: 행=`질의유형`, 값=`이벤트 수`, 필터=이벤트 이름 `ask_question` |
| 답변 실패율(근거 못 찾음) | **탐색 › 자유 형식**: 행=`답변결과`, 값=`이벤트 수` |
| 어떤 법을 많이 찾나 | **탐색 › 자유 형식**: 행=`근거법령`, 값=`이벤트 수` |
| 평균 응답 속도 | **탐색**: 값에 `응답시간` 추가 후 평균 |

`탐색`은 좌측 메뉴의 **탐색(Explore)** → `자유 형식` 템플릿을 선택하고, 좌측
"측정기준" 옆 `+`로 위 표의 맞춤 측정기준을 끌어다 놓으면 된다.

> 운영 개선 관점의 핵심 지표는 **`result = 근거없음` 비율**이다. 이 비율이 높은
> `q_type`이 바로 corpus에 자료가 부족한 영역이므로, 자료 보강 우선순위로 삼으면 된다.

## 5. 운영자(점검용) 접속을 실적에서 빼는 방법

명근이 동작 확인을 위해 수시로 접속하므로, 그 접속은 집계에서 제외한다.
**두 가지 장치가 동시에 걸려 있고, 둘 중 하나만 걸려도 제외된다.**

1. **이름 기준** — 로그인 이름을 `박새` 로 입력하면 GA 스크립트 자체를 불러오지 않는다.
   방문(page_view)·질문·답변 어느 것도 기록되지 않는다. 앞뒤 공백은 무시된다.
   - 제외 이름을 바꾸거나 추가하려면 `chatbot/public/index.html` 의
     `EXCLUDED_USERS` 배열을 수정하고 재배포한다. (예: `["박새", "테스트"]`)
   - **주의**: 이름이 정확히 일치해야 한다. 오타로 입력하면 그 접속은 집계에 잡힌다.
2. **브라우저 기준(백업)** — 주소 뒤에 `?nostat=1` 을 붙여 한 번만 접속하면
   (`https://jeongbi.explozn87.workers.dev/?nostat=1`) **그 브라우저는 이후 계속 제외**된다.
   이름을 잘못 입력해도 안전하다. 점검용 PC·휴대폰에서 한 번씩 해두는 것을 권장.
   - 해제하려면 `?nostat=0` 으로 접속한다.
   - 브라우저 저장소를 지우면(시크릿 모드 포함) 설정이 사라지므로 다시 붙여야 한다.

> GA4에도 '내부 트래픽 제외'(IP 기준) 기능이 있지만, 이 챗봇은 **회사 IP에서 들어오는
> 임직원 사용량이 곧 실적**이므로 IP로 거르면 안 된다. 그래서 위 두 방식을 쓴다.

## 6. 알아둘 제약

- **사내망 차단 가능성** — 측정 스크립트는 `googletagmanager.com` 에서 받아온다.
  회사 방화벽이나 브라우저 광고차단 확장이 이 도메인을 막으면 그 사용자의 이용은
  집계되지 않는다(챗봇 기능 자체는 정상 동작한다). 배포 후 실시간 보고서에 아무것도
  안 잡히면 이 경우를 먼저 의심하고 전산팀에 도메인 허용을 요청할 것.
  차단이 풀리지 않으면, 브라우저를 거치지 않는 **Worker 자체 집계**(Cloudflare KV
  일일 카운터 또는 Analytics Engine)로 대체할 수 있다.
- **집계는 설정 이후부터** — GA4는 소급 집계가 안 된다. 측정 ID를 넣은 시점부터
  쌓이며, 맞춤 정의도 등록 이후 수집분부터 보고서에 반영된다.
- **표준 보고서 반영은 하루 정도 지연**될 수 있다. 즉시 확인은 실시간 보고서로 한다.
- 질의 유형은 키워드 규칙 분류라 100% 정확하지 않다. 예컨대 여러 주제가 섞인 질문은
  위쪽 우선순위 유형 하나로만 잡힌다. 대략의 분포 파악용으로 쓰면 된다.
